## 一、项目概述

在 **iPad（iPadOS）** 上开发一款**原生 App**，帮助用户：

1. **授权登录百度网盘**（百度账号 OAuth 授权）；
2. **浏览并选中**网盘里的资料（视频 / 音频 / 图片 / 文档）；
3. 把选中的内容排成播放列表，**顺序自动连播**（视频、音频连播；图片、文档顺序浏览）。

一句话定位：**一个连接百度网盘、支持"选中即连播"的 iPad 媒体播放器**。

## 三、目标用户与典型场景

- **目标用户**：把大量视频/音频/图片/资料存在百度网盘、希望在 iPad 上"一键连看"的个人用户（如追剧、看网课、听有声书、翻看照片集/资料）。
- **典型场景**：
  1. 用户打开 App → 授权百度网盘 → 进入某个课程文件夹 → 全选 20 个视频 → 点"连播" → 躺着依次看完，中途退出下次能续播。
  2. 挑一个音乐文件夹 → 加入播放列表 → 锁屏后台继续听，锁屏界面能切上/下一首。

## 四、功能需求

### 4.1 账号与授权
- [ ] 百度账号 **OAuth 2.0** 授权登录（首次授权、后续自动登录）。
- [ ] `access_token` 安全存储（Keychain）、**过期自动用 `refresh_token` 刷新**。
- [ ] 显示当前登录用户信息（头像、昵称、网盘容量）。
- [ ] 退出登录 / 解除授权。

### 4.2 文件浏览与选择
- [ ] 目录树浏览（进入文件夹、返回上级、面包屑路径）。
- [ ] 文件列表展示：名称、类型图标、大小、时长（音视频）、缩略图。
- [ ] 排序（名称/时间/大小）与筛选（仅看视频/音频/图片…）。
- [ ] **多选**文件、"全选当前文件夹"。
- [ ] 关键词搜索（可选，二期）。

### 4.3 播放列表
- [ ] 把选中项加入播放列表，支持**拖拽调序**、删除、清空。
- [ ] 列表持久化保存（下次打开还在），支持多个命名列表（可选）。
- [ ] 从任意一项开始播放。

### 4.4 播放与连播（核心）
- [ ] **视频播放**：播放/暂停、进度拖动、快进快退、倍速、音量、亮度、全屏、锁定横屏。
- [ ] **音频播放**：后台播放、锁屏/控制中心控制、Now Playing 信息。
- [ ] **顺序连播**：播完自动切下一个；模式切换（顺序 / 列表循环 / 单个循环 / 随机）。
- [ ] **断点续播**：记住每个文件的播放进度，下次自动从上次位置继续。
- [ ] **图片浏览**：顺序翻页、自动幻灯片（可设间隔）、双指缩放。
- [ ] **文档预览**：PDF/Office 文档顺序预览（PDFKit / QuickLook）。
- [ ] 字幕支持（内嵌/外挂 .srt，二期）。
- [ ] AirPlay 投屏（可选）。

### 4.5 其他
- [ ] 最近播放 / 观看历史。
- [ ] 收藏夹（可选）。
- [ ] 基本设置（默认倍速、连播模式、缓存清理等）。

## 六、技术方案（原生 iPad）

### 6.1 技术栈
- **语言/UI**：Swift + SwiftUI（必要处混用 UIKit）。
- **视频播放**：`AVKit` / `AVPlayer`（mp4/mov/m4v/HEVC 原生）；**mkv/avi/flv/rmvb 等**用 **MobileVLCKit**（VLC 内核）兜底。
- **音频**：`AVPlayer` + `AVAudioSession`（后台播放）+ `MPNowPlayingInfoCenter` / `MPRemoteCommandCenter`（锁屏控制）。
- **图片**：SwiftUI `AsyncImage` / 自定义缓存；文档：`PDFKit` + `QLPreviewController`。
- **网络**：`URLSession` + async/await。
- **存储**：Keychain（Token）、`SwiftData`/CoreData 或本地 JSON（播放列表、历史、进度）。

### 6.2 百度网盘接入（核心链路）

**OAuth 授权（Authorization Code 模式）**
1. App 打开百度授权页 `https://openapi.baidu.com/oauth/2.0/authorize`（`ASWebAuthenticationSession`）。
2. 用户登录并同意 → 回调 `redirect_uri` 带回 `code`。
3. 用 `code` 换 `access_token` + `refresh_token`（`/oauth/2.0/token`）。

**核心 API（xpan 系列）**
| 用途 | 接口 |
|---|---|
| 用户信息 | `/rest/2.0/xpan/nas?method=uinfo` |
| 文件列表 | `/rest/2.0/xpan/file?method=list&dir=/` |
| 搜索 | `/rest/2.0/xpan/file?method=search` |
| 文件详情 + 下载地址(dlink) | `/rest/2.0/xpan/multimedia?method=filemetas&fsids=[...]&dlink=1` |
| 视频转码流(M3U8) | `/rest/2.0/xpan/file?method=streaming`（**需额外权限/配额**） |

### 6.3 播放地址的关键难点 ⚠️（务必重视）

百度返回的下载地址 `dlink` **要求请求头带 `User-Agent: pan.baidu.com`** 才能正常拉流。而 `AVPlayer` 默认发送自己的 UA，**直接把 dlink 丢给 AVPlayer 大概率播不了**。

**对策（原生方案，二选一）：**
- **方案 A（推荐）**：实现 `AVAssetResourceLoaderDelegate`，拦截 AVPlayer 的分段请求，用 `URLSession` 带上 `User-Agent: pan.baidu.com` 转发，并正确处理 **Range 断点续传**，把数据回喂给播放器。
- **方案 B**：App 内起一个本地 HTTP 代理（如 GCDWebServer），AVPlayer 播 `http://127.0.0.1:port/...`，代理层注入正确请求头再转发到百度。

> 备注：官方"转码流(streaming, M3U8)"接口若能申请到，可拿到更适合流播的地址，但该接口通常有**资质门槛和配额限制**，作为增强项。

### 6.4 模块划分
```
App
├─ Auth        授权与 Token 管理（Keychain、自动刷新）
├─ BaiduAPI    网盘 API 封装（list / filemetas / dlink / streaming）
├─ Browser     文件浏览与多选 UI
├─ Playlist    播放列表模型与持久化
├─ Player
│   ├─ VideoPlayer  (AVPlayer + ResourceLoader 注入 UA)
│   ├─ VLCPlayer    (MobileVLCKit 兜底格式)
│   ├─ AudioPlayer  (后台播放 + 锁屏控制)
│   ├─ ImageViewer  (幻灯片)
│   └─ DocViewer    (PDFKit / QuickLook)
├─ Progress    断点续播与观看历史
└─ Settings    偏好设置
```

## 七、百度网盘开放平台申请指南（最先要做）

> 没有通过审核的开发者应用，**任何方案都拿不到网盘数据**，所以这一步要**最先启动、并行进行**。

1. **注册开发者**：访问 **百度网盘开放平台**（`pan.baidu.com/union`），用百度账号登录，进入"开发者中心"。
2. **创建应用**：应用类型选"**软件**"，填写应用名称、简介、平台（iOS）等。
3. **获取密钥**：创建后拿到 **`AppKey`、`SecretKey`、`AppID`**（这三样是接入凭证）。
4. **配置回调地址**：设置 OAuth `redirect_uri`（iOS 可用自定义 URL Scheme 或 Universal Link）。
5. **申请接口权限 / scope**：至少需要 `basic,netdisk`；如需**视频转码流**等高级能力，需单独申请（可能要企业资质）。
6. **提交审核**：按要求补充资料等待审核通过。
7. **注意配额与限制**：接口有 QPS/日调用量限制，`dlink` 有时效性，部分能力个人开发者受限。

**需要你确认/准备的：**
- 是个人开发者还是企业？（企业能拿到更全的接口权限）
- 拿到 `AppKey / SecretKey` 后**私下**提供给我用于联调（**不要写进公开仓库**）。

## 八、关键风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | 百度开放平台**审核不通过 / 权限受限** | 项目最大阻塞 | 最先申请；准备备选（如 WebDAV/其他网盘）作退路 |
| 2 | `dlink` 需特殊 UA，AVPlayer 直连失败 | 视频播不了 | ResourceLoader 或本地代理注入 UA（见 6.3） |
| 3 | mkv/rmvb 等格式 AVPlayer 不支持 | 部分文件无法播 | 集成 MobileVLCKit 兜底 |
| 4 | 接口**限速/限流/dlink 时效** | 起播慢、断流 | 缓存 dlink、失败重试、必要时用转码流 |
| 5 | **App Store 审核**对网盘类客户端较严 | 上架困难 | 自用可走开发者签名/TestFlight；上架需完善隐私政策与合规 |
| 6 | `SecretKey` 泄露风险 | 安全隐患 | 密钥不入库、不硬编码；理想是加一层自有后端做授权中转 |
| 7 | **构建依赖 Mac** | 需求方无 Mac 则无法出包 | 我产出完整 Xcode 工程，构建在你的 Mac 完成 |
